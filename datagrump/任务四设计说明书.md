# 开发任务四设计说明书

## 1. 任务目标

实现动态 RTO 计算和 AIMD 拥塞控制，在发生超时或 ACK 序号缺口时及时降低发送窗口。

## 2. RTO 计算

收到新 ACK 时计算 `SampleRTT = ACK到达时刻 - 数据报发送时刻`。首个样本用于初始化，后续样本按指南公式更新：

```text
EstimatedRTT = 0.875 * EstimatedRTT + 0.125 * SampleRTT
DevRTT       = 0.75 * DevRTT + 0.25 * |SampleRTT - EstimatedRTT|
RTO          = EstimatedRTT + 4 * DevRTT
```

RTO 限制在 10～60000 ms，未收到 RTT 样本前使用 1000 ms。

## 3. AIMD 机制

- 初始拥塞窗口为 1，慢启动门限为 16。
- `cwnd < ssthresh` 时，每个新 ACK 使窗口增加 1，实现慢启动。
- `cwnd >= ssthresh` 时，每个新 ACK 使窗口增加 `1/cwnd`，每个 RTT 约增加 1。
- 发生超时或新 ACK 序号跨过未确认序号时，令 `ssthresh = max(2, cwnd/2)`，再将 `cwnd` 置为 1。
- 接收端对每个数据报单独回复 ACK，避免在未实现重传时因累计 ACK 停滞。

## 4. 实验环境

`run-contest` 使用 20 ms 延迟、`droptail` 队列和 64000 字节有限缓冲区。队列拥塞时的尾丢弃会在 ACK 序号中产生缺口，从而触发乘性减小。

## 5. 结论

控制器能根据 RTT 动态调整超时时间，通过慢启动和拥塞避免提高链路利用率，并在超时或 ACK 序号缺口时及时降低发送窗口。
